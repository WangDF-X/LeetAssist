## 1. 已确认策略与范围

> LLM 填语义；Schema 限制形式；编译器入口语义校验保证关系成立；builder 保证绘制质量。
>
> **关键结构错误拒绝整图；非法标注按条跳过、显式报告部分绘制；内部编译错误不能伪装成标注容错。**

- 保留语义 JSON → 本地编译器 → `WBElement[]` → 白板的架构；AI 和图元库走同一校验/编译入口。
- LLM 不输出坐标、尺寸、字面颜色、Konva 元素或布局引擎参数。
- 优先补入口、语义、资源边界、错误策略、诊断和原子提交；视觉优化留在布局层，不以增加结构种类为本轮目标。
- 保持 Local First、BYOK；不引入外部绘图服务、DOT 输入语言或 Graphviz 运行时依赖。
- 图元库成功产物插入手绘层；AI 成功产物替换覆盖层。**统一编译不等于统一落层**。

## 2. 职责与可信边界

```text
04 完整回复 → 唯一载荷提取 → 标准 JSON 解析 → unknown
                                                ↓
图元库构造对象 ───────────────────────────→ 编译器入口
                                                ↓
               预算预检 → Schema 分区校验 → 语义校验
                                                ↓
                   仅补明确定义的默认值 → 已验证内部类型
                                                ↓
                  builder 布局/元素/锚点 → 有效标注编译
                                                ↓
                       严格 IR 后置检查 → CompileResult
                                                ↓
               调用方校验题目/请求生命周期 → 原子提交
```

| 层 | 必须负责 | 不得承担 |
|---|---|---|
| 04 输出适配 | 流完整性、唯一载荷、大小预检、JSON 解析 | 擅自补值/引用、宽松 JSON 修补、坐标兜底 |
| Schema | 字段、类型、必填/允许项、枚举、版本、形式限制 | 把 TypeScript 类型断言当网络校验 |
| 语义校验 | ID 唯一、引用存在、索引范围、锚点能力、跨字段约束 | 删除关键边/结构、重命名冲突 ID、猜位置 |
| 归一化 | 按协议补可选默认值/缺省 ID | 强转布尔或数字、裁剪数组、截断文字 |
| Builder/布局 | 已验证语义 → 完整主体、几何、锚点 | 分散复制校验规则、默默改变语义 |
| IR 后置检查 | 几何/ID/绑定/预算/内容完整性 | sanitize 坏产物后当作成功 |
| 07/白板命令 | 生命周期检查、原子落层、状态回传 | 第二套解析/校验器、按元素非空推断成功 |

编译器只做计算，不改输入或场景。builder 只接收已验证的内部类型，内部防御性断言失败须报告编译错误。任何边界不得传播未处理异常到 UI。

## 3. 可执行 Schema 与版本

### 3.1 同源定义

- 维护可执行 JSON Schema（JSON 结构校验规范）作为形式规则的权威来源；公开类型、提示词字段说明、Provider 输出约束和示例由它派生或通过一致性检查。
- Schema 方言、生成方式、校验库是工程选型，具体依赖选型不能改变协议。
- Provider 支持结构化输出时可以提前施加同源约束；**所有输入仍必须本地校验**。Provider 的 Schema 子集适配不能放宽本地协议。
- 原有 TypeScript 联合类型仅说明预期形态，不是可执行校验器；禁止将 unknown 强转为 `DslStructure` 后直接送 builder。

### 3.2 输入规则

- 顶层必须是 `LlmDiagram` 对象，`dslVersion` 必填且严格等于新契约版本 `2`。二叉树字段及 gap 能力有语义变化，升版本避免重新解释旧 v1。缺失/其他版本拒绝，不自动推断或迁移。
- 不接受元素数组、裸单结构、字符串对象或别名；04 负责文本解析，03 的公共编译输入为 unknown 对象。
- 每种对象明确必填字段、允许字段、类型和枚举；拒绝未知字段。主体包含 x/y/尺寸/字面颜色等字段即主体错误，不静默剥离。
- `DslValue` 仅为 string、有限 number 或 null。布尔、数组、对象非法；字符串 `"1"` 不自动转数值 1；0/null 不能按 falsy 丢失。
- 索引为非负安全整数；数值有限；字符串/集合必须满足集中长度和数量限制。

### 3.3 分区校验是标注容错的前提

1. 校验 envelope 与全部 structures：任何主体错误返回 error，不调用 builder。
2. `annotations` 缺省合法；若存在必须为数组，否则是 envelope 错误。
3. annotations 数组逐条校验，包括每条内部字段、类型、未知字段及引用。某条为 null、未知 kind、缺 anchor、错误 color 或越界，整条丢弃并记 warning，其余主体/标注不受影响。
4. Provider 可用完整生产 Schema；本地不能把完整 Schema 的任意失败直接当作整图失败，而应按上述主体/标注边界分类。
5. 一条标注多个问题只计一次丢弃；部分有效字段不单独绘制，例如 window 只有一端合法也不能绘制半个窗口。

### 3.4 默认值与兼容

- 校验之后才归一化，仅补已定义的可选默认值；必填内容、值、关系不能补猜。
- 布尔开关缺省 false：indexed/header/doubly/circular/deque/showArray/directed；annotations 与多叉树 children 缺省空数组；二叉节点 left/right 缺省 null；可选显示标签/名称缺省不显示。tree.variant 必填，不猜二叉/多叉。
- 缺省结构 ID 沿用原 structures 索引的 s0/s1…，先登记显式 ID 再生成；发生冲突拒绝，不自动改名。
- 语义引用检查前可在校验器内部计算上述确定性“有效 ID”来解析引用；只有整体验证通过后才输出归一化对象。此预计算不改输入，也不允许先把无效字段转成默认值再校验。
- 被 node 锚点引用的链表/树节点必须显式给 ID；未命名节点只分配内部身份，不对外公布猜测名称。graph/stateMachine 节点 ID 原本即必填；堆的索引 ID 是 §4.2 规定的例外。
- 新图元库、示例和提示词同步为 v2；旧持久化 IR 场景继续按场景版本加载，不因 DSL 升级丢失。编译入口拒绝旧 v1 载荷；未来需要 DSL 迁移时另立规则，不影响已有 IR 恢复。

## 4. 语义引用、锚点与结构规则

### 4.1 身份与引用

- 显式 ID 为非空字符串；结构 ID 图内唯一，节点 ID 在所属结构内唯一。重复主体 ID 拒绝整图；同名标签允许，标签不是 ID。
- 图边、状态转移、initial/accepting 必须引用所属结构的真实实体；不存在即关键结构错误，不跳过该边后成功。协议没有隐式跨结构边。
- 标注先解析结构，再校验锚点种类、实体/索引与结构能力。不可通过标签猜节点，也不能将表头/补出的格子当真实数据锚点。
- 锚点 key 必须无歧义编码字段元组，不能使用未经转义的分隔符拼接；重复 key 是内部错误，禁止 Map 覆盖。
- 布局只改变锚点几何，不能改变 ID、原索引、值顺序或左右/前后关系。

### 4.2 结构核对表

下表为 v2 确认规则；数量及文字限制同时遵守 §6。

| kind | 必查规则 / 确定含义 | 边界规则 |
|---|---|---|
| array | items 原顺序；cell 对应真实数据；indexed 不改变数据 | 允许 items=[]；不开放 gap |
| matrix | rows 各行等长；cell2 数据行列不含表头 | 表头若给严格等于对应行/列数；rows=[] 为 0×0；非空 rows 不允许零列；未计算格显式填 null |
| map | entries 的 key/value 必填；cell2 为条目行及键/值两列 | 禁止重复键，按类型和值比较，数字 1 与字符串 "1" 不同；允许空表 |
| linkedList | 顺序及多值保留；显式 ID 唯一；cell.index 指整个节点 | 每节点 values 为 1–4 项；node.id 同样指整个节点；不开放内部值格；空链允许；非空 circular 至少两节点，单节点环拒绝 |
| stack / queue | 不因布局反转 items 内容 | 栈 items[0] 底、末项顶；队列 items[0] 首、末项尾；允许空 |
| bucket | 桶及桶内顺序保留；空占位不注册成数据 | cell2.col 是桶索引、row 是桶内索引；允许空桶及 buckets=[]；无 window |
| barChart | values 有限且非负，不修改数值、不截标签 | 零保留位置/数值，以零高度标记显示；labels 若给严格同长；允许空 |
| tree | variant 必填 binary/nary；root 可 null；节点 value 必填且可 null | binary 只用 left/right；nary 只用 children；禁止混用；children 不含 null；保留左右缺位语义 |
| heap | values 按完全二叉树索引解释；不排序/堆化/验证堆序 | 允许空；树 node.id 固定 h0/h1…；showArray=true 才提供 cell.index 数组锚点，不映射到树 |
| graph | ID 唯一；端点存在；directed 缺省 false | 允许空；拒绝自环/平行/同对反向边；无向 (a,b)/(b,a) 是重复；label 与 weight 都给显示“label · weight” |
| stateMachine | 状态唯一；转移/初态/终态引用存在 | 允许空，initial 缺省、accepting 缺省 []；accepting 不重复；拒绝自环/平行/同对反向转移 |

- 空结构显示可选 name 及编译器生成的 ∅，不伪造数据项/节点/锚点。顶层 structures 至少 1 项，不能以空图请求代替显式清空。
- 空树 root=null 与值为 null 的真实节点不同。仅右孩子的树必须保留右侧语义，不居中成唯一无方向孩子。
- window 仅开放 array.cell 与 matrix.cell2，见 §4.3.3；gap 不进入 v2 生产 Schema。
- 图/状态机自环、多边、反向双边留待后续连线路径扩展，不静默合并/删边。链表 circular 属于已有独立 builder 能力，不因图的限制全部禁用。
- 图形契约只保证形式和内部关系一致，不能证明模型的算法推理或题意理解正确。值与步骤须来自题面、代码快照或明确示例。

### 4.3 标注专项约定

> 2026-10-19 确认：本节规定标注语义、引用、组合和布局职责；沿用四种标注，v2 暂不开放 gap/边/链表内部值格锚点。

#### 4.3.1 四种标注的职责与字段

| kind | 语义 | 必填字段 | 可选字段 | 不承担的职责 |
|---|---|---|---|---|
| pointer | 用文字命名一个指向实体/位置的变量或游标，例如 i、j、slow | anchor、label | color | 不创建主体关系边，不移动目标，不表示变量更新动画 |
| highlight | 强调一个已有语义实体 | anchor | color | 不改原值，不修改主体元素，不把描边颜色当持久算法状态 |
| window | 表示一个由两个语义边界确定的范围 | from、to | label、color | 不把任意两节点的屏幕包围盒直接解释为合法区间 |
| note | 解释一个实体或整张图的文字 | text | anchor、color | 不作为范围端点、引用目标或主体结构标题 |

- caption 为图级标题，structure.name 为结构标题，note 为解释文字，pointer.label 为指针名，主体节点/边 label 为内容。提示词必须区分，不将解释文字塞入节点值，也不因已有 caption 取消 note。
- 色值仅允许已有语义色枚举；缺省取显式传入的默认色。颜色是视觉强调，不代替 anchor 或文本含义；模型不能靠“蓝色结点”作为引用。
- 沿用建议色含义：blue 当前/活跃，red 目标/失配，green 已完成/命中，orange 临时强调，default 普通；它们不是校验器推断算法正确性的规则。
- 所有文字按纯文本处理，不解释 HTML、Markdown、代码或模板表达式。pointer.label 单行且不全为空白；note.text 可多行但不全为空白；可选 window.label 若给也不可全空白。保留原文，不自动 trim/截断/补写；长度见 §6。
- 四种标注均不得携带 x/y、字号、偏移、车道、zIndex 等几何控制；朝向、尺寸和避让只由编译器决定。

#### 4.3.2 锚点适用表与能力注册

每个 kind 必须有一份明确的 `structure kind × anchor kind × annotation kind` 能力表，校验器与 builder 共同遵循；**Schema 的 DslAnchor 联合不能被理解为任何结构支持任何锚点**。表头/标题/边暂不在现有锚点集合中；需要标注边或具体链表值格时不能临时造 ID/字段，须先扩契约。

| 结构 | pointer/highlight/局部 note 可用锚点 | window 能力 |
|---|---|---|
| array | cell.index 对应 items | 同结构 cell 闭区间 |
| stack / queue | cell.index 对应 items | 不支持 |
| barChart | cell.index 对应 values，包含零值 | 不支持 |
| matrix | cell2.row/col 真实数据格，不含表头 | 同结构二维闭矩形 |
| map | cell2.row 条目，col=0 键、col=1 值 | 不支持 |
| bucket | cell2.col 桶索引、row 桶内索引 | 不支持 |
| linkedList | cell.index 整节点；node.id 显式命名节点 | 不支持 |
| tree / graph / stateMachine | node.id 指节点/状态；树节点须显式命名 | 不支持 |
| heap | node.id=h0/h1… 指树；showArray=true 时 cell.index 指数组 | 不支持 |

- pointer/highlight/有 anchor 的 note 只引用上表实体锚点；gap 首版不支持，任何使用它的标注按 INVALID_ANCHOR 丢弃，生产 Schema 不提供 gap。
- note 无 anchor 表示图级解释，不自动绑定最近结构；有 anchor 但非法时丢弃该 note，不能降级成图级 note。
- 输入引用非法属于单条标注错误；**经语义校验合法的实体却未被 builder 登记锚点属于内部 BUILD_FAILED**，不能再以“锚点不存在”静默跳过。
- 标注引用结构/节点时，04 示例优先显式声明结构 ID 与相关节点 ID，避免模型依赖不明确的缺省节点命名。

#### 4.3.3 范围语义（已确认）

**先定义语义范围，再计算范围几何**。当前“两个 box 并集外扩”的视觉配方不能代替范围规则：折行数组或链表中，端点 box 并集可能漏掉中间元素。

| 输入 | 含义 | 校验 |
|---|---|---|
| 同一 array 的 cell i → cell j | 闭区间 [i,j]，包含两端和全部中间项 | 0≤i≤j<n；i=j 为单项窗口 |
| 同一 matrix 的 cell2 (r0,c0) → (r1,c1) | 两维均包含端点的矩形范围 | r0≤r1、c0≤c1，范围内全部格真实存在 |

- 首版仅开放上表 array/matrix 范围；gap、其他结构的 window 均拒绝该条标注，不按屏幕距离猜范围。
- 拒绝跨结构、混合锚点类型及反向范围，不自动交换端点或取“左上/右下”；非法范围只影响这一条 window。
- range 解析应返回被覆盖实体集合或稳定范围描述，再供布局层计算框；不能只检查两端存在。范围实际几何需包含所有目标的最终 box，不包含无关数据。
- 如果合法范围在某布局下无法忠实用当前 IR 表达，应当调整布局或返回编译失败；不得把所有夹在屏幕之间的实体标成选中。多段范围框需要另行确认，不在本轮添加字段。

#### 4.3.4 同位置多标注与冲突（已确认）

- 允许 i/j 等多个 pointer 共指同一实体、多 note、嵌套/交叉合法窗口；输入顺序是稳定布局优先序，不等于覆盖序。
- 多指针不能合并 label、去重或改指向；编译器按车道/水平错位布局，所有箭头仍落在原锚点。
- 完全相同的标注允许无损视觉去重，保留全部来源索引，不计 droppedAnnotations；比较已解析的实体/范围、原文及有效颜色。不同文字、指针名或颜色不能当重复。
- 同一实体不同有效颜色的 highlight 为冲突（包括链表 cell/node 指同一实体）：保留先出现者，后续冲突条跳过，诊断 ANNOTATION_CONFLICT 并 partial；不使用隐式末项覆盖。
- window 与 highlight/pointer 可以同时存在，window 的色不覆写主体或其他标注颜色。多个合法框重叠不是输入错误，不能只因视觉交叠就跳过有效标注。
- 冲突检测在语义实体解析后、几何生成前执行；无效的早期标注不占用实体颜色。不同结构同名 ID 不会被误认为同一实体。

#### 4.3.5 布局、图层与后置检查

- 延续描边高亮、指针文字+箭头、范围描边框、纯文本 note；不修改主体，现有渲染管线不增加持久元素类型。
- spec §4.6 的固定间距是**首选布局常量**，不是不得移动的契约；重叠时调整车道/间距，不让模型提供偏移来救布局。
- 多结构排布需要预留其有效标注区域；局部 note/pointer 不能因主体先堆叠而落到下一结构上。图级 note 在所有结构/局部标注排布后安排，多个图级 note 分行放置。
- caption 在含有效标注的整体边界外布置；window 标签、结构标题、数组下标、note 和 pointer 文字均参与度量与空间预留。锚点始终来自主体最终几何，不来自覆盖描边。
- 视觉顺序固定为主体 → 范围框/高亮 → 指针箭头 → 标注文字 → caption；同层保持稳定输入顺序及来源映射，不按随机 ID 排序。
- 校验完整文字未裁剪、箭头目标正确、框覆盖预期范围、最终坐标/预算合法；内部不变量失败整图 error。
- 合法组合仅有视觉拥挤且语义仍可辨时给 LAYOUT_OVERLAP warning，不增加 droppedAnnotations、不把 ok 改 partial。UI 将布局提示与标注缺失分开；warning 不得掩盖错误目标或遗漏实体。
- 无重叠的完整保证不作为本轮承诺；多指针避让等视觉目标须有专项回归用例，而不是仅验证“不抛异常”。

#### 4.3.6 输出边界示例

下例演示 v2 的同项双指针、高亮和局部 note；编译器必须保留全部语义并安排文字/箭头车道，示例不能代替验收。

{
  "dslVersion": 2,
  "structures": [{ "id": "nums", "kind": "array", "items": [2, 7, 11] }],
  "annotations": [

## 5. 失败策略与返回契约

### 5.1 状态定义

| 情形 | 状态 | 行为 |
|---|---|---|
| 非法 envelope/版本/主体字段、重复 ID、缺失关键引用、主体语义不支持、总预算超限 | error | 拒绝整图，无可提交元素，保留旧画面 |
| 单条标注字段/引用/索引/能力错误，其余编译完整 | partial | 完整主体 + 其他有效标注；显式报告未绘制条数 |
| 主体 builder 异常、有效标注内部异常、重复锚点、坏 IR | error | 丢弃暂存整批，不伪装成输入 warning |
| 全部合法且完整编译 | ok | 返回完整产物，等待调用方提交 |

- partial **仅表示非法标注未绘制**，不得用于部分结构、边、单元格或 IR 元素丢失。
- 全部标注无效但主体完整时仍为 partial，提示“标注均未绘制”。
- 错误捕获在边界完成：输入错误按协议分类；内部错误返回安全诊断，不泄露异常堆栈，不能吞掉后返回 ok。

### 5.2 诊断与结果

```ts
interface DiagramDiagnostic {
  code: string; // 稳定错误码，不用中文 message 作分支依据
  severity: "error" | "warning";
  stage: "schema" | "semantic" | "normalize" | "layout" | "annotation" | "output";
  path: string; // JSON Pointer，根为 ""，如 /structures/0/edges/2/to
  message: string; // 简明、安全，不拼接原始载荷/代码/凭据/堆栈
  annotationIndex?: number; // 原始 annotations 索引
}

type CompileResult =
  | { status: "ok" | "partial"; elements: WBElement[];
      droppedAnnotations: number; diagnostics: DiagramDiagnostic[] }
  | { status: "error"; elements: []; droppedAnnotations: 0;
      diagnostics: DiagramDiagnostic[] };
```

- error 的 droppedAnnotations=0 表示没有实际提交，不代表输入标注有效；问题细节由 diagnostics 表达。
- 状态不变量：ok 的 droppedAnnotations=0 且无错误诊断；partial 的 droppedAnnotations>0 且无错误诊断；error 至少一条 error 诊断。partial 计数按原始标注索引去重，不按诊断条数计算。
- 非丢弃型布局 warning 不构成 partial；ok 可以附布局提示。ANNOTATION_CONFLICT / LAYOUT_OVERLAP 的触发规则见 §4.3。
- 最小错误码：INVALID_ENVELOPE、UNSUPPORTED_VERSION、INVALID_FIELD、UNKNOWN_FIELD、LIMIT_EXCEEDED、DUPLICATE_ID、UNKNOWN_REFERENCE、INVALID_ANCHOR、INDEX_OUT_OF_RANGE、UNSUPPORTED_SEMANTICS、BUILD_FAILED、INVALID_IR。
- 主体/内部问题 severity=error，非法标注 severity=warning；诊断保持稳定顺序（阶段、输入路径），按集中条数上限限制输出并附省略摘要。
- ANNOTATION_CONFLICT 为 semantic warning；LAYOUT_OVERLAP 为 layout warning；诊断 stage 表示发现问题的阶段，不表示出现该阶段就一定丢弃标注。
- 旧 dropped/warnings 接口迁移为此契约；所有调用点同步更新。若短期兼容，旧字段必须从新结果派生，不保留第二套失败语义。

## 6. 资源预算与防御性输入

- 集中定义 limits：载荷字节、JSON 嵌套深度、结构/标注数、节点/边/格子数、单值文本长度、树深度、IR 元素数、几何范围、诊断数。
- 必须有单结构与整图累计预算，避免许多小结构绕过限制；下标文字、表头、堆双表示、连线与标注展开都计入产物预算。
- limits 与提示词/Schema/测试同源，采用下列已确认初始阈值；后续调整须更新本表并验证 Chrome/Edge，不在代码中分散写死。

| 项目 | 上限/定义 |
|---|---|
| 单份 JSON | 128 KiB，UTF-8 字节；对象入口也检查等价可序列化大小 |
| structures | 1–12 |
| annotations | 64 |
| 累计数据项/节点/格子 | 512；array/stack/queue/heap/barChart 每项计 1；matrix 每格计 1；map 每条目计 2；linkedList 每节点计 1、每值格另计 1；tree/graph/stateMachine 每节点计 1；bucket 每桶计 1、每值计 1 |
| 显式 graph edges / stateMachine transitions | 整图累计 512；隐式结构边仍计最终 IR 预算 |
| 树深度 | 16，根为第 1 层；内部 heap 也检查 |
| JSON 对象/数组嵌套深度 | 64，根为第 1 层；与树语义深度分别检查 |
| 最终 IR | 4096 元素，计标题、空态、下标及标注；文本不拆成绕过预算的无界元素 |
| 诊断 | 50 条，含省略摘要；不影响按全部原标注统计丢弃数 |
| 值/节点/边 label、name、caption、window.label、ID | 每字段 200 Unicode 码点；ID 非空且非全空白 |
| pointer.label | 32 Unicode 码点、单行且非全空白 |
| note.text | 500 Unicode 码点，可多行但非全空白 |
| 几何 | 沿用 IR 坐标 ±100000、尺寸 ≤100000、字号 8–72；整体宽高 ≤100000 |

- 单结构使用相同 512 数据单位/512 显式边上限，整图累计仍为 512，不能以多个结构倍增；所有局部文字/深度上限独立生效。linkedList 每节点 1–4 值格的结构限制仍保留。
- Unicode 码点计数须跨浏览器一致；现有 sanitizer 若按 UTF-16 单元处理，须同步调整或严格检测，不能截断已通过校验的非 BMP 字符。
- 初始预算须通过图元库最大参数组合及边界回归；它们是接受上限，不是性能保证。既有模板最大树为 85 节点、矩阵 144 格，低于数据预算；产物仍须实际检查。
- 载荷大小在解析前检查；解析后遍历采用有界/迭代策略，在展开前计数与检查深度，不能深度递归到栈溢出后才拦截。
- unknown 对象入口也检测环引用等非 JSON 形态，受控失败；不能认为只有网络文本才是不可信输入。
- Builder 生成过程检查累计预算，超限立即整图失败，不继续无界分配，不裁剪内容以假装成功。
- 单条标注的字段限制（例如 label 太长）作为该条输入错误丢弃；载荷大小/集合总数/累计处理预算属于整图限制，超限 error。有效标注展开使最终 IR 超预算也为 error，不能通过丢弃本来合法的标注凑预算。
- 等于阈值允许，超过阈值拒绝，提示缩小示例；不能自动截断数组、标签或删除边。不得在日志中包含 API Key、用户代码或原始载荷。

## 7. Builder 与 IR 后置条件

- 已验证类型包含明确的默认值与语义身份；builder 不依赖未知对象的类型强转。
- 保留所有主体值、顺序与关系；不能自动排序/堆化/去重/补矩阵数据/截断 label。无法忠实表达时报错。
- 同一 DSL + 编译版本/配置产生稳定几何、元素顺序和锚点。随机 IR ID 可不同；测试注入确定性 ID。颜色/线宽显式传入，不暗取全局状态。
- 文字度量、图形边界、连线绑定、锚点几何共用 spec §4.4 的纯函数接口；尺寸适配后锚点登记最终几何。
- 后置检查：几何全部有限且在 IR 范围内；尺寸有效；ID 全局唯一；绑定目标存在且合法；label 未丢失/截断；必需锚点完整；元素数和整体包围盒受预算约束。
- 历史场景加载的 sanitize 容错不适用于新编译批次。若 sanitizer 会 clamp/截断/补 ID/解绑/丢元素，编译返回 error，不提交被修过的部分图。居中平移后的最终批次也须符合几何边界。
- 先保证完整、受控、不崩溃，不承诺任意复杂图无交叉。长文字适配、多指针车道、标注空间预留在布局层迭代；需新增曲线路径/端口/DSL 字段则另行确认。

## 8. 原子提交与生命周期（联动 07）

- 编译时用暂存数组和锚点表，不先清空旧 overlay；03 纯编译结果不自动写场景。
- error 不插入元素、不清空旧覆盖层、不改视口、不新增撤销记录或成功状态；显式清空是独立用户操作。
- ok/partial 一次性提交。partial 是完整新主体 + 有效标注替换旧图，不能追加半份结构来掩盖失败。
- 04/07 携带请求发起时的 problemId、requestId、sourceMessageId；开始编译与实际提交前都检查题目和请求有效性，不能把回复到达时的当前题目当原请求目标。
- 新作图请求使同目标旧待提交请求失效；切题、取消、显式清空、面板卸载也使相关请求失效。旧回复晚到不得覆盖新图、串题或恢复已清空的图。
- 过期结果明确回传 STALE_REQUEST，不自动缓存/重放；目标未挂载回传 TARGET_UNAVAILABLE。
- UI：ok 为“已绘制”；partial 为“主体已绘制 · N 条标注未绘制”，可查看安全原因与路径；error 为失败/未应用。旧图还在不代表本次成功。
- 异步实现也遵守相同边界；是否采用异步不改变提交前检查和原子性。

## 9. 验收矩阵与实现顺序

### 9.1 必须落实的自动化用例

| 类别 | 用例 | 核心断言 |
|---|---|---|
| 正例 | 12 结构、多结构、4 标注、中文、0/null | 内容完整、后置条件满足、输入不变 |
| Schema | 缺/未知版本、裸结构、错类型、非有限数值、未知坐标字段 | error、无可提交元素、不进入主体 builder |
| 主体语义 | 重复 ID、显式与缺省 ID 冲突、缺边端点/状态引用 | 不删边/改名后成功，整图拒绝 |
| 标注容错 | null、未知 kind、缺 anchor、错误 color、越界、错误锚点种类 | partial、主体/其他标注完整、计数与路径正确 |
| 组合错误 | 一条多问题、所有标注非法、主体和标注同时错误 | 按条计数、全标注无效仍 partial、主体 error 优先 |
| 内部异常 | builder 抛错、有效标注生成异常、重复锚点、坏 IR | 受控 error、整批不提交 |
| 预算 | 阈值内/等于/超限、累计超限、深树、环引用对象 | 有界运行、不裁剪、不无界分配 |
| 布局 | 稳定 ID、重复编译、调整尺寸后标注 | 几何稳定，锚点仍指原实体 |
| 标注语义 | pointer/note/highlight 职责、无锚 note、非法锚 note | 不猜位置、不改主体、不将局部 note 降级为全局 note |
| 标注不变量 | 合法引用但 builder 缺锚点；范围框只覆盖端点 | 缺锚点为内部 error；范围按实体集合检查，不漏中间项 |
| 标注组合 | i/j 同位置、重复标注、多色高亮、嵌套窗口、多全局 note | 不丢合法文字/箭头；冲突诊断按条；几何与来源稳定 |

| 视觉提示 | 有效标注拥挤、标题/下标/局部标注/多结构相邻 | warning 与丢弃分开；无暗改目标或值；最终边界合法 |
| 集成 | 旧图上 error/partial/ok，晚到请求、切题、清空、取消 | 保留旧图或原子替换；无串图/复活旧图 |

### 9.1.1 双浏览器冒烟验收
